ENTIDADES
1. Cliente
   Atributos: id, nombre, tipo, empresa, RUC, email, teléfono, contraseña
   PK: id  |  FK: (vacío)

2. Dirección
   Atributos: id, clienteId, dirección, referencia, distrito, ciudad, departamento
   PK: id  |  FK: clienteId → Cliente

3. Categoría
   Atributos: id, nombre, descripción
   PK: id  |  FK: (vacío)

4. Producto
   Atributos: id, categoriaId, nombre, descripción, medidas, material, colores, precioReferencialPEN, stock, imagen, estado
   PK: id  |  FK: categoriaId → Categoría

5. Carrito
   Atributos: id, clienteId, fechaActualizacion
   PK: id  |  FK: clienteId → Cliente

6. DetalleCarrito
   Atributos: id, carritoId, productoId, cantidad
   PK: id  |  FK: carritoId → Carrito; productoId → Producto

7. Pedido
   Atributos: id, clienteId, direcciónId, fecha, estado, total
   PK: id  |  FK: clienteId → Cliente; direcciónId → Dirección

8. DetallePedido
   Atributos: id, pedidoId, productoId, cantidad, precioUnitario, subtotal
   PK: id  |  FK: pedidoId → Pedido; productoId → Producto

9. Pago
   Atributos: id, pedidoId, método, monto, estado, fecha
   PK: id  |  FK: pedidoId → Pedido

10. MovimientoInventario
   Atributos: id, productoId, tipoMovimiento, cantidad, motivo, fecha
   PK: id  |  FK: productoId → Producto

RELACIÓN Y PROTECCIÓN DE DATOS
Los datos se relacionan mediante claves primarias y foráneas, manteniendo la integridad entre clientes, productos, carritos, pedidos, pagos e inventario.
Si se intenta borrar un cliente que ya tiene pedidos, el sistema debe impedir su eliminación física para conservar el historial de ventas de Mueblería Paraíso.
Para evitar eliminaciones accidentales, solo el administrador autorizado debe gestionar estos registros y el sistema debe solicitar una confirmación antes de realizar la acción.
En lugar de eliminar a un cliente con historial, se puede desactivar su cuenta y conservar sus pedidos para mantener la información de las ventas realizadas.
Si ocurre una eliminación por error, las copias de seguridad periódicas de la base de datos permitirán recuperar la información.
Los datos que requieren mayor protección son las contraseñas, correos, teléfonos, RUC y datos de pago; las contraseñas deben almacenarse mediante hash y el acceso debe controlarse mediante permisos.

CONCLUSIÓN
El DER de Mueblería Paraíso organiza los datos necesarios para implementar su futura tienda virtual. Permite gestionar clientes, direcciones, categorías, productos, carrito, pedidos, pagos e inventario de forma relacionada. El modelo se adapta a las necesidades reales de Mueblería Paraíso y considera tanto clientes finales como empresas u organizaciones. Esta estructura servirá como base para las siguientes sesiones y para la futura implementación de la tienda en WordPress/WooCommerce.
